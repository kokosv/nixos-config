# NixOS Configuration

> [!Note]
> Managed with flake-parts and home-manager. Uses the [dendritic pattern](https://github.com/mightyiam/dendritic) — every `.nix` file under `modules/` and `hosts/` is auto-imported as a flake-parts module. No central aggregator. Adding a module means creating one file.

## Setup from fresh install

```bash
# Add git to the live environment
nix-env -iA nixos.git

# Clone the configuration
git clone https://github.com/kokosv/nixos-config.git
cd nixos-config

# Copy the autogenerated hardware config into the host directory
cp /etc/nixos/hardware-configuration.nix hosts/<hostName>/_<hostName>/

# Switch to this configuration
sudo nixos-rebuild switch --flake .#<hostName>
```

> `hardware-configuration.nix` lives under each host's `_<hostName>/` directory and is tracked normally in git (not gitignored).

```bash
sudo nixos-rebuild switch --flake ~/.nixos-config#vps --target-host root@31.70.105.226
```

Builds locally, copies result to the VPS over SSH. Requires your SSH key to be authorized on the VPS as root.

## Structure

```
nixos-config/
├── flake.nix                        # mkFlake — auto-imports modules/ and hosts/
├── flake.lock
├── agenix-rules.nix                 # access control for agenix secrets
├── hosts/                           # Host assembly files (auto-imported)
│   ├── kt480/
│   │   ├── kt480.nix                # Picks modules for kt480
│   │   └── _kt480/                  # _ prefix = excluded from auto-import
│   │       ├── hardware-configuration.nix
│   │       └── disko.nix
│   ├── vps/
│   │   ├── vps.nix                  # Picks modules for vps
│   │   └── _vps/
│   │       └── disko.nix
│   ├── _homeserver.nix              # Skeleton
│   ├── _klegion.nix                 # Skeleton
│   └── _mc-server.nix               # Skeleton
├── modules/
│   ├── system/                      # NixOS system modules  →  config.nixos.*
│   ├── home/                        # Home-manager modules  →  config.homeManager.*
│   │   ├── _nvim/plugins/           # nvim plugin sub-files (excluded)
│   │   └── _zsh/config/             # zsh config sub-files (excluded)
│   ├── vps/                         # VPS-specific modules  →  config.vps.*
│   ├── homeserver/                  # Homeserver modules    →  config.homeserver.*
│   └── mc-server/                   # MC server modules     →  config.mcServer.*
└── notes/                           # Reference notes, never imported
```

### The `_` prefix rule

Any file or directory whose name starts with `_` is **excluded** from auto-import. Use it for:
- Hardware/disk configs (`kt480/_kt480/`, `vps/_vps/`)
- Sub-files imported manually by a parent module (`_nvim/`, `_zsh/`)
- Non-`.nix` assets (`_keyboard/bg-phonetic-dvorak`)

## How Modules Work

Every module file follows the same pattern — it declares a flake-parts option and sets it to a NixOS/home-manager module value:

```nix
# modules/system/ssh-server.nix
{ lib, ... }: {
  options.nixos.sshServer = lib.mkOption { type = lib.types.deferredModule; };

  config.nixos.sshServer = {
    services.openssh.enable = true;
    # ...
  };
}
```

The host file (`hosts/kt480/kt480.nix`) picks exactly which modules to use — no `enable = false` flags:

```nix
modules = (with config.nixos; [
  networking 
  sshServer 
  hardware 
  customization
]) ++ [ ... ]
```

### Adding a system module

Create `modules/system/my-service.nix`:

```nix
{ lib, ... }: {
  options.nixos.myService = lib.mkOption { type = lib.types.deferredModule; };

  config.nixos.myService = { pkgs, ... }: {
    services.my-service.enable = true;
    environment.systemPackages = [ pkgs.my-service ];
  };
}
```

Then add `myService` to the modules list in `hosts/kt480/kt480.nix`. Done — no aggregator to touch.

### Adding a home module

Same pattern under `modules/home/`, using `options.homeManager.<name>` and adding it to the `home-manager.users.koko.imports` list in `hosts/kt480/kt480.nix`.

### Adding a module that needs sub-files

Create a `_<name>/` directory next to the main `.nix` file. Sub-files are regular NixOS/home-manager modules imported explicitly by the parent:

```nix
# modules/home/my-app.nix
config.homeManager.myApp = { pkgs, ... }: {
  imports = [
    ./_my-app/extra-config.nix
  ];
  # ...
};
```

## Secrets (agenix)

Secrets (SSH keys, passwords, API tokens) are stored as encrypted `.age` files in `secrets/` and committed to the repo. At boot, NixOS decrypts them with the machine's SSH host key and places the result in `/run/agenix/` (tmpfs — never written to disk between reboots).

### Layout

```
agenix-rules.nix     # access control — which public keys decrypt which secrets
secrets/
└── *.age            # encrypted secret files (safe to commit)
```

### Adding a new secret

1. Declare it in `agenix-rules.nix`:
   ```nix
   "secrets/my-secret.age".publicKeys = allHosts;
   ```
2. Create the encrypted file (opens `$EDITOR`, save the plaintext, it gets encrypted on exit):
   ```bash
   nix run github:ryantm/agenix -- -e secrets/my-secret.age
   ```
3. Reference the decrypted path in `hosts/<host>/<host>.nix`:
   ```nix
   age.secrets.my-secret.file = ../../secrets/my-secret.age;
   # available at runtime as /run/agenix/my-secret
   ```
4. Rebuild the affected host:
   ```bash
   nixreb <kt480|klegion|vps|mc|hm>
   ```

### Adding a new host

1. Get the host's SSH public key: `cat /etc/ssh/ssh_host_ed25519_key.pub`
2. Add it as a variable in `agenix-rules.nix` and include it in `allHosts` (or per-secret groups)
3. Re-encrypt all secrets so the new host can decrypt them:
   ```bash
   nix run github:ryantm/agenix -- -r
   ```

### Commands (always run from repo root)

```bash
cd ~/.nixos-config

nix run github:ryantm/agenix -- -e secrets/ssh-private-key.age   # edit existing secret
nix run github:ryantm/agenix -- -e secrets/new-secret.age        # create new secret
nix run github:ryantm/agenix -- -r                                # re-encrypt after adding a host key
```

## Recovery Key

A standalone `age` identity exists purely as a disaster-recovery backdoor. Unlike every other recipient in `agenix-rules.nix` (host keys, personal SSH key), it is **not tied to any machine's disk** — its private key lives only in the password manager, so wiping or losing any single host (including the one holding the `koko` key) can never fully lock us out of secret decryption again.

> [!Important]
> The private key is **never** committed to this repo and never written to any host's disk long-term. Only its public key (`age1...`) lives in `agenix-rules.nix`, as the `recovery` variable.

Use it in one of two situations:

### 1. Decrypt a single secret directly

You just need to read a secret's contents (e.g. to recover a value, or inspect what's there) — no changes to recipients needed.

```bash
cat > /tmp/recovery.txt <<'EOF'
<paste the private key from the password manager>
EOF
chmod 600 /tmp/recovery.txt

nix run github:ryantm/agenix -- -d secrets/ssh-private-key.age -i /tmp/recovery.txt

shred -u /tmp/recovery.txt   # clean up when done
```

### 2. Re-key everything (e.g. a host lost its registered key)

A host's SSH host key changed (reinstall, hardware swap, etc.) and it's no longer a valid recipient on the existing `.age` files. Update `agenix-rules.nix` with the host's new public key first, then re-encrypt every secret using the recovery identity to decrypt the old ciphertext:

```bash
git clone https://github.com/kokosv/nixos-config.git   # or use an existing checkout
cd nixos-config

cat > /tmp/recovery.txt <<'EOF'
<paste the private key from the password manager>
EOF
chmod 600 /tmp/recovery.txt

# edit agenix-rules.nix: update the affected host's key variable

nix run github:ryantm/agenix -- -r -i /tmp/recovery.txt

git add agenix-rules.nix secrets/*.age
git commit -m "rekey after <host> lost its registered key"
git push

shred -u /tmp/recovery.txt   # clean up when done
```

Rebuild the affected host(s) afterward (`nixreb <host>`) to pick up the newly decryptable secrets.

## Usage

### Other useful commands

```bash
# Preview changes without applying
sudo nixos-rebuild dry-activate --flake .#kt480

# Update all flake inputs
nix flake update

# Update a single input
nix flake update nixpkgs
```
