# NixOS Configuration

> [!Note]
> Managed with flake-parts and home-manager. Uses the [dendritic pattern](https://github.com/mightyiam/dendritic) — every `.nix` file under `modules/` and `hosts/` is auto-imported as a flake-parts module. No central aggregator. Adding a module means creating one file.

## Setup from fresh install

```bash
# Add git to the live environment
nix-env -iA nixos.git

# Clone the configuration
git clone https://github.com/kokosv/nixos-config.git
cd nixos-config

# Copy the autogenerated hardware config into the host directory
cp /etc/nixos/hardware-configuration.nix hosts/_<hostName>/

# Stage it so Nix can see it (it is gitignored, never committed)
git add -f hosts/_<hostName>/hardware-configuration.nix

# Switch to this configuration
sudo nixos-rebuild switch --flake .#<hostName>
```

> `hardware-configuration.nix` is gitignored (`hosts/_*/hardware-configuration.nix`).
> It must be staged with `git add -f` after every `nixos-generate-config` update.

## Structure

```
nixos-config/
├── flake.nix                        # mkFlake — auto-imports modules/ and hosts/
├── flake.lock
├── hosts/                           # Host assembly files (auto-imported)
│   ├── kt480.nix                    # Picks modules for kt480
│   ├── vps.nix                      # Picks modules for vps
│   ├── homeserver.nix               # Skeleton
│   ├── mc-server.nix                # Skeleton
│   ├── _kt480/                      # _ prefix = excluded from auto-import
│   │   └── hardware-configuration.nix   # gitignored, stage with git add -f
│   └── _vps/
│       └── disk-config.nix
├── modules/
│   ├── system/                      # NixOS system modules  →  config.nixos.*
│   ├── home/                        # Home-manager modules  →  config.homeManager.*
│   │   ├── _nvim/plugins/           # nvim plugin sub-files (excluded)
│   │   └── _zsh/config/             # zsh config sub-files (excluded)
│   ├── vps/                         # VPS-specific modules  →  config.vps.*
│   ├── homeserver/                  # Homeserver modules    →  config.homeserver.*
│   └── mc-server/                   # MC server modules     →  config.mcServer.*
└── notes/                           # Reference notes, never imported
```

### The `_` prefix rule

Any file or directory whose name starts with `_` is **excluded** from auto-import. Use it for:
- Hardware configs (`_kt480/`, `_vps/`)
- Sub-files imported manually by a parent module (`_nvim/`, `_zsh/`)
- Non-`.nix` assets (`_keyboard/bg-phonetic-dvorak`)

## How Modules Work

Every module file follows the same pattern — it declares a flake-parts option and sets it to a NixOS/home-manager module value:

```nix
# modules/system/ssh-server.nix
{ lib, ... }: {
  options.nixos.sshServer = lib.mkOption { type = lib.types.deferredModule; };

  config.nixos.sshServer = {
    services.openssh.enable = true;
    # ...
  };
}
```

The host file (`hosts/kt480.nix`) picks exactly which modules to use — no `enable = false` flags:

```nix
modules = (with config.nixos; [
  networking sshServer hardware customization
  # trackpoint intentionally omitted — not present on kt480
]) ++ [ ... ]
```

### Adding a system module

Create `modules/system/my-service.nix`:

```nix
{ lib, ... }: {
  options.nixos.myService = lib.mkOption { type = lib.types.deferredModule; };

  config.nixos.myService = { pkgs, ... }: {
    services.my-service.enable = true;
    environment.systemPackages = [ pkgs.my-service ];
  };
}
```

Then add `myService` to the modules list in `hosts/kt480.nix`. Done — no aggregator to touch.

### Adding a home module

Same pattern under `modules/home/`, using `options.homeManager.<name>` and adding it to the `home-manager.users.koko.imports` list in `hosts/kt480.nix`.

### Adding a module that needs sub-files

Create a `_<name>/` directory next to the main `.nix` file. Sub-files are regular NixOS/home-manager modules imported explicitly by the parent:

```nix
# modules/home/my-app.nix
config.homeManager.myApp = { pkgs, ... }: {
  imports = [
    ./_my-app/extra-config.nix
  ];
  # ...
};
```

## Usage

### kt480 (local aliases defined in zsh config)

```bash
nixreb    # sudo nixos-rebuild --flake ~/.nixos-config#kt480 switch   (rebuild + activate)
nixbld    # sudo nixos-rebuild build --flake ~/.nixos-config#kt480    (build only, no switch)
nixtst    # sudo nixos-rebuild test --flake ~/.nixos-config#kt480     (activate without making permanent)
```

### Other useful commands

```bash
# Preview changes without applying
sudo nixos-rebuild dry-activate --flake .#kt480

# Update all flake inputs
nix flake update

# Update a single input
nix flake update nixpkgs
```
